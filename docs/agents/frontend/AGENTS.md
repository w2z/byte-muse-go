# 前端 Agent 专项规范

先读取仓库根目录 `AGENTS.md`；本文件由根入口按任务显式加载，不依赖 docs 目录的自动发现。本文约束相关业务源码，历史记录不是现行指令。

## 六、前端 Agent 职责与验收

### 6.1 输入与设计

- 开始前确认业务切片、对标页面、API 契约、状态字典、组件体系、目标浏览器和屏幕范围。
- 没有旧前端源码时，以对标系统实际页面为视觉和交互证据；无法确认部分标为新设计，不声称完全复刻。
- 先梳理入口、布局、操作、加载、空数据、错误、无权限、提交中和成功状态，再编码。

### 6.2 UI 库与公共样式

- 使用统一 UI 库和设计令牌。跨页面视觉规则进入公共主题、公共样式或基础组件层。
- 禁止在个别页面直接覆盖 UI 库内部类、使用全局穿透选择器、复制组件样式或用高优先级和 !important 临时压制问题。
- 页面级样式仅处理该页面独有布局和语义表现；样式需要在第二个页面复用时，优先提升为公共样式或公共组件变量。
- 修改公共组件样式前检查全部消费者，并验证桌面和约定响应式范围。
- 统一间距、颜色、字体、层级、圆角、表单、按钮、表格、弹窗、图片比例、骨架屏和空状态。

#### 6.2.1 列表筛选栏栅格规范

- 下载任务按用户指定采用 Arco Table 表头筛选，不再保留独立筛选栏；影片列只排序，其余数据列表头同时提供筛选和排序，操作列不参与。此页面不套用筛选栏栅格，规范测试须检查表头入口完整性及远程查询，不能直接免检。

- 所有现有及新增列表筛选栏必须使用 Arco `Grid.Row` / `Grid.Col`，从 `@arco-design/web-react` 导入 `Grid`。不得用自定义 CSS Grid、`auto-fit`、`auto-fill` 或分列媒体查询重复实现栅格。
- 行统一设置 `gutter={[12, 12]}`、`justify="start"`、`align="center"`；每个筛选条件及操作按钮组统一设置 `xs={24} sm={12} md={8} xl={4}`。Arco 为24栅格，桌面每项占4格表示一行六等份，不得误写成每项占6格（一行四份）。
- 响应式沿用 Arco 断点：视口小于576px为单列，576px起两列，768px起三列，1200px起六列。条件不足时保留剩余空间，不得拉伸已有条件填满整行。
- 每个条件包含可见中文标题和对应控件；日期范围也只占一列，不得单独跨两列。空间不足时可在列内将标题放到控件上方，不改变该条件的栅格份额。
- 搜索、查询、重置等操作组成一个 `Grid.Col`，紧跟最后一个筛选条件，组内居左、按钮间距8px。禁止使用 `space-between`、自动左外边距、offset或弹性占位把按钮推到屏幕右端；需要换行时仍居左。
- CSS只负责列内标题、控件、按钮的排列及容器留白，不再控制筛选栏列数或覆盖 Arco 内部栅格样式。标签页列数调整控件放在操作组之后，窄屏隐藏时连同其列一起隐藏，避免空白占位。
- 本规范适用于所有影片、演员、标签、搜索、下载任务、日志、榜单及后续新增列表筛选页；设置表单、登录表单和编辑弹窗不自动套用六等份规则。保留各页面已确认的Tabs、分隔条和分页布局。
- 验收必须覆盖实际浏览器390/576/768/1280/1920px宽度，核对列宽一致、条件少时留白、日期不跨列、按钮位置及筛选栏无横向溢出；同时验证搜索、重置及筛选后的分页行为。

### 6.3 业务与公共能力

- 服务端状态是权威；前端只做展示转换和即时反馈，不复制订阅资格、筛选和任务完成规则。
- 所有页面只能通过统一请求客户端访问真实 API；不得在开发运行时注入 Mock 或假数据。
- 统一请求库负责基址、认证、超时、取消、序列化、错误归一化和必要重试；页面不得散落底层请求。
- 图片预览、加载失败、骨架屏、空状态、分页、消息、确认框等公共能力统一封装。
- 处理重复点击、重复提交、请求竞态、过期响应、路由切换取消、筛选分页和刷新恢复。

### 6.4 浏览器强制验收

页面或组件完成后必须启动实际应用并使用浏览器检查。必要截图放操作系统临时目录，不进入仓库，并在输出前遮蔽敏感信息。

至少验证：

- 首次加载、骨架屏、空状态、正常数据、接口失败和无权限。
- 所有按钮、链接、菜单、下拉、分页、弹窗、表单提交、取消和返回均可用，无无效点击。
- 页面切换流畅，无明显闪烁、残留遮罩、布局跳动、状态串页或过期请求回写。
- CSS 无错位、溢出、遮挡、异常滚动、层级错误、文字截断和图片比例异常。
- 控制台无业务异常、未处理 Promise、资源失败和框架警告；网络请求符合契约。
- 覆盖任务约定的桌面尺寸和响应式断点，关键页面逐项对比对标系统。

代码审查、单元测试、构建或静态截图不能代替浏览器交互验收。发现问题后修复并重跑相关场景。

### 6.5 前端交付

交付页面、组件、公共样式、API 封装、必要测试、浏览器场景、临时截图位置及控制台和网络结果。明确哪些页面使用真实 API、哪些仍为 Mock、哪些状态未验证。

前端 Agent 的最小开工顺序：登录对标系统并记录对应页面 → 定位业务入口和全部状态 → 读取冻结 API 契约 → 搜索已有页面、组件和公共样式 → 确认复用或扩展方案 → 实现 → 类型检查和构建 → 浏览器逐项交互 → 检查控制台与网络 → 把真实 API 联调结果交给主 Agent。

## 补充视觉与数据规则

- 页面名称由面包屑承担，PageHeader仅输出无障碍h1，不重复显示标题和顶部工具栏。
- 输入框、选择框与按钮沿用Arco默认32px，不在页面重复设置size；控件文字14px、表单纵向间距20px。
- 列表分页复用shared/ui/ListPagination，服务端先过滤再分页；切换条件或页长回第一页，页长必须符合各接口上限。标签全部列表和日志的专用页长不强制改成常规页长。窄屏页码在上，总数与页长在下。
- IMAGE_MODE=INVISIBLE时共享卡片不得加载真实封面、剧照或海报，封面位置显示统一占位图；缺少图片地址时使用同一占位图。筛选输入保持草稿/已应用状态；空条件及相同条件搜索仍发起查询。
- 执行 `npm run check:standards`、相关测试、类型检查和构建。规范检查只验证受支持的源码声明，不替代浏览器布局及业务验收。新增筛选栏必须使用filter-toolbar或role=search标记，纳入自动扫描；复杂封装需扩展检查，不能绕过。
